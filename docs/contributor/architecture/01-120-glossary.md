# Glossary

| Term                        | Definition                                                                                                                                                                                                         |
|-----------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ADR                         | Architecture Decision Record — a short document capturing a significant architectural decision, the context in which it was made, and its rationale. Stored in `docs/adr/`.                                         |
| Audit Log                   | A record of API server access and operations. Kyma Infrastructure Manager (KIM) maps each cluster's tenant ID to an external audit log backend using the converter configuration. Audit logging is mandatory by default (`--audit-log-mandatory`).   |
| SAP BTP                     | SAP Business Technology Platform — SAP's cloud platform for building, integrating, and extending business applications. It is the commercial platform on which SAP BTP, Kyma runtime is offered as a managed service. |
| Converter Configuration     | A JSON file loaded by KIM at startup (and reloaded on change) that defines provider-specific defaults: Kubernetes versions, machine image versions, networking CIDR ranges, and audit log backend mappings.          |
| CRD                         | Custom Resource Definition — a Kubernetes extension mechanism that defines a new API object type. KIM defines the Runtime and GardenerCluster CRDs.                                                            |
| FSM                         | Finite State Machine — the orchestration pattern used by Runtime Controller. Each step of the provisioning workflow is a `stateFn` function. The FSM loop calls state functions in sequence until done or requeued. |
| Garden cluster              | The Kubernetes cluster that hosts the Gardener API server and the Shoot CRs for a given Gardener project. KIM accesses the Garden cluster using a dedicated kubeconfig.                                           |
| Gardener                    | An open-source Kubernetes-native system for managing the full lifecycle of Kubernetes clusters across multiple cloud providers. KIM uses Gardener's Shoot API as its cluster provisioning backend.                 |
| GardenerCluster             | A KIM-defined CRD (legacy) used to represent a managed cluster for the purpose of kubeconfig rotation. Managed by the GardenerCluster Controller.                                                                  |
| KCP                         | Kyma Control Plane — the cluster on which KIM runs. Runtime and GardenerCluster CRs are created in the `kcp-system` namespace on this cluster.                                                                 |
| KEB                         | Kyma Environment Broker — the component responsible for creating, updating, and deleting Runtime CRs in response to user actions in SAP BTP. KEB is the primary consumer of KIM's API.                                |
| KIM                         | Kyma Infrastructure Manager — this system. A Kubernetes operator that manages the lifecycle of Gardener-based Kubernetes clusters for the Kyma environment.                                                         |
| Kubeconfig                  | A YAML file containing connection credentials (server URL, CA certificate, client token) for a Kubernetes cluster. KIM generates time-limited kubeconfigs for Kyma clusters and stores them as Secrets in `kcp-system`. |
| Kyma                        | An open-source cloud-native application runtime built on Kubernetes, maintained by SAP. It provides a set of modules for extending and connecting applications in a Kubernetes environment. See also: SAP BTP, Kyma runtime. |
| SAP BTP, Kyma runtime       | The managed, commercial offering of Kyma on SAP Business Technology Platform (SAP BTP). Users provision SAP BTP, Kyma runtime clusters via the SAP BTP Cockpit; KIM manages the underlying Kubernetes cluster lifecycle for these clusters. |
| kyma-system                 | The namespace created on every Kyma cluster by KIM as part of post-provisioning configuration. Kyma modules are installed into this namespace.                                                                        |
| OIDC                        | OpenID Connect — an identity layer on top of OAuth 2.0. KIM configures the Kubernetes API server on each Kyma cluster to trust one or more OIDC providers, enabling federated authentication.                                |
| Registry Cache              | A Gardener extension (`registry-cache`) that caches container images on the cluster nodes to reduce pull latency and bandwidth. KIM configures this extension when it finds a RegistryCacheConfig CR in the Kyma cluster.   |
| RegistryCacheConfig         | A CRD defined by the Registry Cache module and deployed on Kyma clusters. Users create instances of this CRD to request registry caching. KIM reads these CRs and propagates the configuration to Gardener.     |
| Runtime                     | The primary CRD managed by KIM. A Runtime CR represents a single Kyma cluster and contains the full desired state for provisioning (provider, region, workers, networking, OIDC, security, cache configuration).   |
| Runtime Bootstrapper        | An optional component installed by KIM on Kyma clusters after provisioning. It installs base Kyma components required for module management.                                                                          |
| Runtime Watcher             | A component (external to KIM) that watches Kyma clusters for CR changes and emits events to KIM.                                          |
| Shoot                       | The Gardener CRD representing a managed Kubernetes cluster. KIM creates and manages Shoot resources in the Garden cluster.                    |
| SKR                         | Shoot Kubernetes Runtime — the Kubernetes cluster provisioned by Gardener for a given `Shoot` CR. This is the cluster that end users interact with; it runs their applications and Kyma modules.                    |
| stateFn                     | A Go function type (`func(context.Context, *fsm, *systemState) (stateFn, *ctrl.Result, error)`) that represents a single step in the Runtime Controller's Finite State Machine.                                     |
| systemState                 | The data structure passed between FSM state functions. It holds the current Runtime CR instance and any intermediate data accumulated during the reconciliation cycle.                                              |
